# 🎮 猫娘小游戏 v0.5.7

> 这一版新增了**棋类对弈（六种棋）**，并把「陪伴 / LLM / 渲染」三条通道彻底收归插件本体——
> 游戏只负责玩法与数据，怎么说话、用什么心情、图怎么画，全在插件一处决定。

## ✨ 本版亮点

### ♟️ 棋类对弈：一个入口，六种棋

说「**下棋**」猫娘会列出棋种，你挑一个就开局（也可以直接说棋种名）：

| 棋种 | 棋盘 | 落子怎么报 |
|---|---|---|
| 五子棋 | 15×15 交叉点 | 坐标，如 `H8` |
| 黑白棋（翻转棋 / 奥赛罗） | 8×8 格心 | 坐标，如 `d3` |
| 中国象棋 | 9×10 交叉点 | 起点终点，如 `b3 b7` |
| 四子棋 | 7 列 6 行 | 报一列，如 `d`（或写 4） |
| 围棋 | 9×9 交叉点 | 坐标如 `d4`；不想下说「**过**」 |
| 国际象棋 | 8×8 格心 | 起点终点，如 `e2 e4` |

- **落子即出图**：每一手都会渲染一张**棋盘图**发到聊天窗——交叉点摆法（围棋/五子棋/象棋）
  与格心摆法（黑白棋/国际象棋）分别处理，带**坐标标签**、**最后一手高亮**与星位标记
- **三档难度**（随手 / 正常 / 认真）、**悔棋**（默认 3 次，双方各回一手）、
  **认输**、**换棋种**、**棋盘重发**、「再来一局」
- **边下边聊**：你落子后可以顺口说句话，猫娘会先接你的话再走棋；你迟迟不动，
  她会自己找个话头催你（阈值/次数/节流都在插件里）
- 棋盘图由插件的 **`board` 版式块**渲染——游戏只提交行列数据，不画一行样式

### 🫧 统一陪伴层（`core/companion.py`）

台词、心情、闲聊、局中主动搭话全部收归插件，游戏只报"发生了什么"：

- **台词三级降级**：LRU 缓存 → LLM 生成 → 该游戏 `emotion.json` 模板（任何一步失败都不会哑火）
- **心情由事件驱动**：`highlight / win / lose / chat / nudge` … 直接推动猫娘的情绪弧线，
  她此刻的心情会写进提示词，影响语气长短与活泼程度
- **情绪延续**：台词模型可以在句尾附带 `{"mood": "proud", "intensity": 0.8}`——
  这段控制指令会被剥掉（不给用户看），只用来让后续台词延续同一种情绪
- **主动搭话策略只在一个地方**：静默阈值、次数上限、间隔节流都在 `should_nudge()`，
  游戏不再各写一套计时器

### 🧠 LLM 网关（`core/llm_gateway.py`）

游戏需要"生成内容"（出题 / 剧情 / 文案）时**只声明场景名**，其余交给网关：

- 按 **场景 + 内容哈希** 缓存（带 TTL），同类内容不重复烧 token
- 调用失败/超时**不抛异常**，退回 fallback，游戏侧不需要写 try
- **按场景统计**调用数 / 命中缓存数 / 失败数，面板与日志都能看到
- 游戏里**禁止**再直接摸 LLM provider（契约测试会拦）

### 🔄 人格热更新（`core/persona.py`）

猫娘人设现在从**宿主角色配置**读取，并做了缓存与热重载：

- 带文件签名（mtime + size）+ TTL：文件一改或宿主"换了当前猫娘"就重新解析，平时零开销
- 换角色时**清空台词缓存**，不会还挂着上一位的说话口吻
- 昵称、自称、核心特质、口头禅、在意/讨厌的事都从人设里取，游戏完全不碰

### 📦 出厂内容随升级刷新（`core/config_manager.py`）

`help.json / keywords.json / emotion.json` 属于**出厂内容**：升级时按字节比对同步进
用户数据目录；而 `config.json` 是**你的设置**，永不被覆盖。

> 这修掉了一个很坑的老问题：用户目录下只要曾经存在过 `config/`，
> 之后升级带来的新帮助/关键词/情感模板就**永远不会补上**——
> 表现是"帮助图打不开，只回一句『X 玩法帮助：』"。

### 🧪 契约测试（新增）

- `test_adapter_contract.py`：静态扫描 `games/**`，出现 `self.push_text*` /
  `self.send_page(` / `self.render_card(` / `self._llm` / `_QUIPS =` 即判违规
  （白名单只留图库本体）
- `test_keyword_style.py`：keywords 不许跨游戏重复/子串截胡，也不许单字词
- 另有 `test_all_games_smoke` / `test_game_switch` / `test_persona_refresh` /
  `test_llm_gateway` / `test_boardgame` / `test_companion` 等用例

## 🐛 本版修复

- **陪伴层心情映射写错 id（静默失效）** — 原来写 `excited/curious`，而情绪弧线的规范
  id 是 `excitement/curiosity`；`Mood.trigger` 对未知 id 静默忽略，于是"赢了猫娘也不兴奋、
  提示词里的心情永远是平静"。现在用规范 id + 别名归一（`excited`、`兴奋` 都能懂），
  并补了 14 项回归测试。
- **推送被宿主拒绝却当成成功** — `push_message` 对超限内联图不抛异常，只回一条
  `rejected: reason=payload_too_large` 回执；现在把 rejected 当失败，继续走下一档通道
  （原生 → 上传 → markdown），不再"以为发了其实没图"。
- **棋类关键词覆盖不全** — 补齐 `西洋棋 / 翻转棋 / 奥赛罗 / 五连 / 四连棋 / 对弈` 等叫法。
- **棋类帮助内容不全** — 简介原只写 4 种棋（现补齐六种），分组改为
  `选棋种 / 六种棋 / 对局操作`，并补标题与副标题。
- **发布校验缺标准仓库文件** — 补齐插件仓库的 `.vscode/settings.json` 与
  `.vscode/tasks.json`（市场标准脚手架文件），并把入口写成规范形式，
  恢复市场的**入口静态检查**。这两条校验已镜像成本地测试，
  避免再出现"本地全绿、一发布就被卡"的情况。

## 📦 仓库与发布

- 仓库补上市场标准脚手架文件（`.vscode/settings.json`、`.vscode/tasks.json`），
  在 VS Code 里可直接跑 `N.E.K.O: check / sync / build` 任务。
- `plugin.entry` 采用规范写法 `plugin.plugins.neko_arcade:NekoArcadePlugin`：
  宿主加载时对"外部安装"会自动规范化为 `plugins.neko_arcade`，内置 / 外部两种安装形态通用。
- 发布校验规则（标准仓库文件、入口类装饰器）已镜像进 `tests/test_smoke.py`。

## 🎮 怎么开始

聊天里说游戏名就行：「**下棋**」「**钓鱼**」「**修仙**」「**塔罗牌**」「**猫猫进化**」。
不会玩就说「**帮助**」，或「**修仙帮助 战斗**」这种"游戏名 + 帮助 + 玩法名"；
也可以直接说指令名（如「我的纳戒」）看那一项怎么用。

## 📥 安装

1. 把下面的 `neko_arcade.neko-plugin` 导入 N.E.K.O
2. 插件管理 → 启用「猫娘小游戏」
3. 直接聊天开玩喵
